# N-42.1 — Carry-to-delivery motion path

**Bottom line:** N42.1 changes the held-prize return from a diagonal leg to an implemented L-shaped path—ascend to the lift top, traverse at Y = 2.8, descend at the chute lane, then release at the unchanged authored release position—without changing N42 delivery semantics.

## Retain

- The existing `beginLift()` behavior is retained: the claw ascends straight up from the grab point while keeping grab X/Z, reaching the lift-top height Y = 2.8.
- The return is split into two deterministic position-keyframed legs using the existing `ClawTravelAnimator`: a horizontal top traverse to `[chute X, 2.8, chute Z]`, followed by a vertical descent to `chute.releasePosition`.
- The existing `returning` state and `returnReached` completion are retained, with completion gated until the descent leg reaches the authored release position.
- N42’s delivery authority remains the chute sensor intersection. The release position remains `[1.05, 1.87, 0.55]`, so the drop-through-sensor geometry and win path are unchanged.
- The implementation scope is limited to `src/effects/n7-coordinator.ts` and, optionally, `src/physics/config.ts` for a canonical `chute.overPosition` waypoint owned by physics configuration.
- Verification passed on 2026-08-04: the focused N7 suite passed (10 tests), including the fixed-step L-shaped motion fixture; the unchanged N42 suite passed; typecheck, lint, full tests (14 files / 85 tests), and build passed (72 modules transformed).

## Caveats

- The pasted N42.1 contract is authoritative and labels the root-cause findings as verified, but this vault draft does not independently re-audit the target repository source.
- The vault outline had no N42.1 row before this draft. The target repository contains `records/task-packets/N42.1-carry-delivery-motion-path.md`; its Workstream/verification section now records the approved implementation and gate results rather than creating a second contract with different semantics.
- The approved return-duration split preserves the 700 ms total budget: 450 ms for the top traverse plus 250 ms for descent.
- Release remains at the authored `releasePosition` Y = 1.87 after the down-leg, preserving N42’s drop-through-sensor geometry.
- The contract baseline is `main @ 3b8bb05`, while the working tree contains preserved N41/N42 implementation changes. No source baseline or working-tree change is made by this documentation draft.

## Do not infer

- Do not infer that N42.1 changes the chute sensor, delivery predicate, countdown, payout hook, prize reset/removal path, or any other N42 win semantic.
- Do not infer that the fix adds a state-machine state, changes the fixed-step policy, changes collision groups, or changes the evidence shape.
- Do not infer that the claw may descend while X/Z are still changing: the top traverse must hold Y within travel tolerance, and the down-leg must hold chute-lane X/Z within travel tolerance.
- Do not infer that a passing N42 delivery suite alone proves the motion-path defect is fixed; the deterministic N7 motion fixture is the path-specific evidence.
- The automated evidence does not replace the requested live-app visual check; that manual check is not claimed here because it was not run by the test suite.
